# Apex Support Guide

**Official support server:** https://discord.gg/ezFVnB5eNB

Apex support is provided through the official Discord support server above.

## General Support

For questions about Apex, start by explaining what you are trying to do, which server feature is involved, and what result you expected.

Include the command name and whether you used a slash command, prefix command, or hybrid command when relevant.

## Command Problems

For a command that fails or behaves unexpectedly, provide:

- The exact command you used, without secrets.
- Whether it was slash, prefix, or hybrid.
- The error message or visible result.
- What you expected to happen.
- Steps that reproduce the problem.
- A screenshot when it helps explain the issue.

## Configuration Problems

When a feature is not behaving as configured, mention the feature, the relevant settings, and which channel, role, or category is involved. Avoid posting tokens, API keys, passwords, or other confidential values.

## Permission Problems

Tell support which action is failing and what permissions Apex has in the relevant channel/server. Discord permissions, channel overwrites, and missing administrative permissions can prevent otherwise supported actions from working.

## Role Hierarchy Problems

If Apex cannot manage a member or role, check whether Apex's highest role is above the target role/member and whether the required Discord permission is enabled. Include a screenshot of the relevant role order when needed.

## Welcome System Problems

For Welcome or Farewell issues, include the configured channel, whether the feature is enabled, the type of welcome/farewell message being used, and the exact behaviour you are seeing.

## Invite Tracking Problems

For invite tracking issues, explain whether the problem is with detecting an invite, identifying the inviter, updating invite counts, or sending invite logs. Include the server context and approximate time of the affected join when possible.

## Security Problems

For Antinuke, AntiBetray, AutoMod, logging, or other security issues, describe the triggering action, configured threshold or module, action that Apex took or failed to take, and any relevant logs.

Potential vulnerabilities should be reported privately through the support server rather than publicly posted.

## Bug Reports

A useful bug report includes:

- A concise description.
- The affected command or feature.
- Exact reproduction steps.
- Expected behaviour.
- Actual behaviour.
- Error messages, screenshots, or relevant logs where appropriate.
- Apex/project version information when known.
- Relevant server/channel/role context, without exposing private or sensitive information.

## What Not to Share

Never post your bot token, API keys, passwords, credentials, or other secrets in support channels. Do not include private user information or sensitive server information unless it is necessary and appropriate for the investigation.
